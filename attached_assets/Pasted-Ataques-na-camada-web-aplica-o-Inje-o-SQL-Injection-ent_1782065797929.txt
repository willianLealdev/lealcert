Ataques na camada web/aplicação
Injeção

SQL Injection — entrada do usuário indo direto pra query sem sanitização/parametrização
Command Injection — input do usuário sendo passado pra um shell/exec
NoSQL Injection — se usar Mongo ou similar em algum ponto

Autenticação e sessão

Brute force de login (por isso rate limiting é essencial)
Credential stuffing (senhas vazadas de outros sites testadas em massa)
Session hijacking — roubo de cookie de sessão (mitigado com httpOnly, secure, sameSite nos cookies)
Fixação de sessão
Senhas mal armazenadas (sempre hash com bcrypt/argon2, nunca texto puro — pelo log, parece que vocês já fazem isso)

Cross-site

XSS (Cross-Site Scripting) — script malicioso injetado via input não sanitizado, executando no navegador de outros usuários
CSRF (Cross-Site Request Forgery) — site malicioso forçando o navegador da vítima a fazer requisição autenticada no seu site
CORS mal configurado — e aqui é literalmente o seu caso agora: CORS é uma proteção, mas configurada errado pode tanto bloquear o legítimo (seu problema atual) quanto, se ficar liberado demais (origin: "*" com credentials), abrir brecha de roubo de dados

Outros

IDOR (Insecure Direct Object Reference) — usuário trocando um ID na URL/request e acessando dados de outro usuário porque a API não verifica permissão
Mass assignment — usuário enviando campos extras no JSON que a API aceita sem filtrar (ex: virar role: admin sozinho)
Path traversal — manipulando caminho de arquivo pra acessar arquivos fora da pasta esperada (relevante pro seu upload de arquivos)
SSRF (Server-Side Request Forgery) — se a API faz requisições pra URLs fornecidas pelo usuário
Rate limit / DoS em endpoints custosos (ex: geração de certificado, envio de email)
Upload malicioso — arquivo disfarçado de imagem mas que é executável, ou arquivo muito grande causando exaustão de disco/memória

Ataques na infraestrutura

Exposição de variáveis de ambiente / secrets (você tem senhas em texto plano no compose — funciona, mas idealmente usar secrets do EasyPanel)
Portas/serviços expostos sem necessidade (ex: Postgres acessível publicamente sem firewall)
Falta de HTTPS / downgrade attack (você já está usando HTTPS, ótimo)
Dependências vulneráveis (pacotes npm desatualizados com CVEs conhecidas)
Container rodando como root sem necessidade
